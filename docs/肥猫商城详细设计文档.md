## 1. 系统概述

### 1.1 系统简介

肥猫商城系统是一个基于Django框架开发的综合性电商平台，集成了商品管理、订单处理、支付结算、会员管理、抽奖营销、POS收银、供应商管理等核心功能。系统采用前后端分离架构，支持多终端访问，提供完整的电商解决方案。

### 1.2 系统目标

- 提供稳定、高效的电商交易平台
- 支持多种支付方式和订单管理
- 实现用户会员体系和积分管理
- 提供营销活动功能（抽奖、优惠券等）
- 支持线下POS收银系统
- 实现供应商和库存管理
- 支持人脸识别登录等创新功能

### 1.3 技术栈

#### 后端技术
- **框架**: Django 3.2.25
- **数据库**: MySQL 8.0
- **缓存**: Redis 6.0
- **搜索**: Whoosh (全文搜索)
- **异步任务**: Celery
- **人脸识别**: face_recognition
- **支付**: 支付宝、微信支付

#### 前端技术
- **框架**: Vue.js 2.x
- **UI组件**: Bootstrap 4
- **图表**: ECharts
- **模板引擎**: Jinja2
- **构建工具**: Webpack

#### 部署技术
- **Web服务器**: Nginx 1.18
- **应用服务器**: uWSGI 2.0
- **容器化**: Docker & Docker Compose
- **监控**: Prometheus + Grafana

#### 3.2.5 临期商品管理功能设计

##### 3.2.5.1 临期商品业务说明

临期商品管理是指对即将过期的商品进行监控、预警、促销和处理的完整管理流程。系统根据商品的生产日期和保质期自动计算过期日期，对临期商品进行分类管理，帮助商家减少库存损失。

**业务场景**
- 商品即将过期需要降价促销
- 顾客需要查看临期商品优惠信息
- 管理员需要设置临期预警规则
- 系统自动推送临期商品提醒

**临期分类**
- **临期预警期**: 距离过期30天内的商品
- **临期促销期**: 距离过期15天内的商品
- **临期紧急期**: 距离过期7天内的商品
- **已过期**: 已超过过期日期的商品

##### 3.2.5.8 临期商品功能特点

1. **自动监控**: 系统定时扫描商品保质期，自动识别临期商品
2. **分级管理**: 根据剩余保质期分为预警、促销、紧急三个等级
3. **自动促销**: 根据临期等级自动应用不同的促销折扣
4. **智能预警**: 临期商品自动发送通知给管理员
5. **用户推荐**: 临期商品在首页和分类页优先展示
6. **统计报表**: 提供临期商品统计和损失分析
7. **灵活配置**: 管理员可自定义临期天数和折扣比例

**会员等级分类**

| 等级 | 等级值 | 名称 | 折扣率 | 积分倍数 | 说明 |

| 普通会员 | 0 | 普通会员 | 1.00 | 1.0 | 默认注册用户 |
| 银卡会员 | 1 | 银卡会员 | 0.95 | 1.2 | 消费满1000元 |
| 金卡会员 | 2 | 金卡会员 | 0.90 | 1.5 | 消费满5000元 |
| 钻石会员 | 3 | 钻石会员 | 0.85 | 2.0 | 消费满10000元 |

**会员等级升级规则**

- 普通会员 → 银卡会员：累计消费满1000元
- 银卡会员 → 金卡会员：累计消费满5000元
- 金卡会员 → 钻石会员：累计消费满10000元
- 会员等级只升不降

**积分获取规则**

- 普通会员：消费1元获得1积分
- 银卡会员：消费1元获得1.2积分
- 金卡会员：消费1元获得1.5积分
- 钻石会员：消费1元获得2积分

### 4.4 数据库优化策略

#### 4.4.1 索引优化
- 为常用查询字段建立索引
- 使用复合索引优化多条件查询
- 定期分析索引使用情况，删除无用索引

#### 4.4.2 查询优化
- 使用`select_related`和`prefetch_related`减少查询次数
- 避免N+1查询问题
- 使用`only()`和`defer()`只查询需要的字段

#### 4.4.3 分表分库策略
- 订单表按时间分表
- 日志表按用户ID分表
- 大表考虑垂直拆分

### 8.5 POS挂单取单功能设计

#### 8.5.1 挂单取单业务说明

挂单功能允许收银员在收银过程中将当前未完成的订单暂时保存，以便处理其他紧急事务或接待其他顾客。取单功能允许收银员将之前挂起的订单恢复到收银界面继续处理。

**业务场景**
- 顾客临时离开，需要先处理其他顾客
- 收银员需要交接班或处理其他紧急事务
- 顾客需要补充商品或修改订单
- 系统故障或网络中断时的临时保存
